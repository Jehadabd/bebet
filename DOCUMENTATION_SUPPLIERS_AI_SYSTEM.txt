-----------------------------------------------
الوصف العام:
-----------------------------------------------
هذه الشاشة هي البوابة الرئيسية لإدارة الموردين. تعرض قائمة بجميع الموردين مع
إحصائيات شاملة عن الديون والمشتريات والتسديدات.

-----------------------------------------------
الاستايل والتصميم (UI/UX):
-----------------------------------------------

1.  لون الخلفية: Color(0xFFF8FAFC) - رمادي فاتح جداً
2.  AppBar: أبيض مع عنوان "نظام الموردين الذكي"
3.  بطاقات الإحصائيات: بيضاء مع ظل خفيف، عرض 220px، ارتفاع 100px
4.  بطاقة المورد: بيضاء مع حواف دائرية (8px)، تحتوي على:
    - أيقونة ملونة (أحمر للديون، أخضر للتعامل النقدي)
    - اسم المورد ورقم الهاتف
    - الرصيد الحالي
5.  زر الإجراءات: أزرق في الزاوية السفلى اليسرى (FloatingActionButton)

-----------------------------------------------
الدوال الرئيسية:
-----------------------------------------------

1.  _loadSuppliers()
    - الوصف: تحميل قائمة الموردين من قاعدة البيانات
    - الاستدعاء: initState()
    - العملية: 
      * استدعاء _suppliersService.ensureTables()
      * استدعاء _suppliersService.getAllSuppliers()
      * تحديث الحالة (_applyFilter)

2.  _applyFilter()
    - الوصف: تطبيق فلتر البحث والتصنيف
    - المدخلات: _searchController.text, _filterType
    - المنطق:
      * البحث في اسم الشركة ورقم الهاتف
      * تصفية حسب: 'all' | 'with_debt' | 'no_debt'

3.  _onAddSupplier()
    - الوصف: فتح شاشة إضافة مورد جديد
    - الانتقال: AddSupplierScreen
    - المعالجة بعد العودة: _insertSupplier()

4.  _insertSupplier(Supplier s)
    - الوصف: إدراج مورد جديد في قاعدة البيانات
    - الاستدعاء: _suppliersService.insertSupplier(s)
    - التحديث: _loadSuppliers()

5.  _openSupplierDetails(Supplier supplier)
    - الوصف: فتح شاشة تفاصيل المورد
    - الانتقال: SupplierDetailsScreen
    - التحديث بعد العودة: _loadSuppliers()

6.  _askTypeThenPick()
    - الوصف: اختيار نوع العملية (فاتورة/سند) ثم اختيار ملف
    - Dialog: يعرض خيارين - فاتورة شراء | سند قبض
    - الاستدعاء التالي: _pickFileAndOpenAI()

7.  _pickFileAndOpenAI()
    - الوصف: اختيار ملف وإرساله للاستخراج الذكي
    - FilePicker: pdf, png, jpg, jpeg
    - الانتقال: AiImportReviewScreen
    - المفاتيح المستخدمة: GEMINI_API_KEY, GROQ_API_KEY, CLOUDFLARE_API_TOKEN

8.  _buildStatsHeader()
    - الوصف: بناء شريط الإحصائيات العلوي
    - البطاقات:
      * عدد الموردين
      * إجمالي الفواتير
      * حجم المشتريات
      * إجمالي التسديد
      * إجمالي الديون

9.  _buildSupplierCard(Supplier supplier)
    - الوصف: بناء بطاقة عرض مورد واحد
    - الألوان: أحمر للمدين، أخضر للتعامل النقدي
    - البيانات: الاسم، الهاتف، الرصيد

-----------------------------------------------
الوصف العام:
-----------------------------------------------
خدمة للتعامل مع Google Gemini API مع دعم 3 مفاتيح للتبديل التلقائي.

-----------------------------------------------
المتغيرات الرئيسية:
-----------------------------------------------

1.  apiKey, apiKey2, apiKey3
    - مفاتيح API للتبديل بينها

2.  _apiKeys
    - قائمة المفاتيح المتاحة

3.  _currentKeyIndex
    - فهرس المفتاح الحالي

4.  _endpoint
    - رابط API: gemini-flash-latest

-----------------------------------------------
الدوال الرئيسية:
-----------------------------------------------

1.  Constructor
    - بناء قائمة المفاتيح المتاحة
    - طباعة عدد المفاتيح المحملة

2.  _switchToNextKey()
    - التبديل للمفتاح التالي
    - الإرجاع: true إذا نجح، false إذا انتهت المفاتيح

3.  _postWithRetry({required Map<String, dynamic> body})
    - الوصف: إرسال طلب مع إعادة المحاولة والتبديل بين المفاتيح
    - maxAttemptsPerKey: 1 محاولة لكل مفتاح
    - timeout: 60 ثانية
    - معالجة الأخطاء:
      * 429: تجاوز الحصة → تبديل فوري
      * 401/403: مفتاح غير صالح → تبديل فوري
      * 500/502/503/504: أخطاء خادم → إعادة محاولة
      * TimeoutException: انتهاء المهلة → تبديل
      * SocketException: خطأ اتصال → تبديل
    - التراجع الأسي: delay = 2^attempt * 300ms + jitter

4.  sendMessage(String message, {List<String>? conversationHistory})
    - إرسال رسالة نصية والحصول على رد
    - temperature: 0.7
    - maxOutputTokens: 1024

5.  extractTextFromPrompt(String prompt)
    - استخراج نص من رد JSON

6.  _buildInvoiceExtractionPrompt({List<Map<String, dynamic>>? products})
    - بناء البرومبت لاستخراج الفاتورة
    - يتضمن:
      * قائمة المنتجات للمطابقة
      * قواعد استخراج الوحدات (meter/piece)
      * قواعد المطابقة (ترجمة، رموز مختصرة)
      * هيكل JSON المطلوب

7.  extractInvoiceOrReceiptStructured()
    - استخراج بيانات من صورة/PDF
    - الإرجاع: Map<String, dynamic> مع بيانات الفاتورة

                     القسم الثاني عشر: ملاحظات تقنية
═══════════════════════════════════════════════════════════════════════════════

1.  مفاتيح API المطلوبة في .env:
    - GEMINI_API_KEY (الأساسي)
    - GEMINI_API_KEY_2 (احتياطي)
    - GEMINI_API_KEY_3 (احتياطي)
    - GROQ_API_KEY (احتياطي)
    - OPENROUTER_API_KEY (احتياطي)
    - CLOUDFLARE_API_TOKEN (احتياطي)
    - CLOUDFLARE_ACCOUNT_ID (احتياطي)

2.  قيود Groq:
    - لا يدعم PDF مباشرة → يحتاج تحويل
    - الحد الأقصى: 4MB Base64
    - يحتاج User-Agent header

3.  حساب التكلفة:
    - للمنتجات بالقطعة: السعر ÷ التعبئة
    - للمنتجات بالمتر: السعر ÷ (الكمية × الأمتار)
    - مثال: 364,800 ÷ (2 × 100) = 1,824 للقطعة

4.  التسلسل الهرمي للوحدات:
    - قطعة (1)
    - باكيت (10 قطع)
    - كرتون (10 باكيت = 100 قطعة)
